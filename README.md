# In-Vehicle Coupon Acceptance

가게 사장님을 위한 **선별 발송형 쿠폰 알림 시스템**을 목표로 하는 프로젝트입니다.
주변을 지나는 모든 운전자에게 알림을 뿌리는 대신, 지금 상황에서 쿠폰을 받을 가능성이 높은 운전자만 골라 자동으로 알림을 보냅니다.
그 판단의 근거가 되는 수락 예측 모델을 설문 데이터로 만들고, 관찰에서 모델링까지 모든 결정을 근거와 함께 기록합니다.

## 서비스 구상

**사용자는 가게 사장님입니다.** 사장님은 쿠폰의 업종과 유효 시간만 정합니다. 누구에게 언제 보낼지는 시스템이 결정합니다.

**시스템은 운전자의 현재 상황을 보고 수락 가능성을 계산합니다.** 목적지, 동승자, 날씨, 시각, 가게까지의 거리와 방향, 그리고 운전자의 평소 방문 습관이 입력입니다.
수락 가능성이 기준 이상인 운전자에게만 알림이 나가고, 나머지는 아예 받지 않습니다.

이 구조에서 모델이 해야 할 일은 두 가지입니다.

- **분류.** 운전자와 상황을 "보낼 대상"과 "보내지 않을 대상"으로 나눕니다. 알림을 받은 사람 중 실제로 수락하는 비율이 핵심 지표가 됩니다. 수락하지 않을 사람에게 보낸 알림은 비용이자 피로이기 때문입니다.
- **설명.** 왜 지금 이 운전자가 대상으로 뽑혔는지, 유효 시간을 바꾸면 대상이 얼마나 늘어나는지 사장님에게 보여줄 수 있어야 합니다.

따라서 전체 정확도보다 **발송 대상으로 분류한 집단의 수락률(정밀도)** 과, 발송 기준을 조절했을 때 **대상 수와 수락률 사이의 균형**을 중요하게 봅니다.

## 문제 정의

입력은 운전 상황(목적지, 동승자, 날씨, 시각), 쿠폰 속성(업종, 유효 시간, 거리, 방향), 운전자 특성(인구통계, 평소 방문 습관)이고, 출력은 수락 확률입니다.
이 확률에 발송 기준을 적용해 알림 여부를 결정합니다.

실제 서비스에서는 처음 보는 운전자를 판단해야 하므로, 모델 평가도 **학습에 쓰이지 않은 응답자**에 대해 이루어져야 합니다.

## 데이터

UCI Machine Learning Repository의 [In-Vehicle Coupon Recommendation](https://archive.ics.uci.edu/dataset/603/in+vehicle+coupon+recommendation) 데이터셋을 사용합니다.
Amazon Mechanical Turk 설문으로 수집되었으며, 응답자 한 명이 약 22개의 가상 운전 상황에 대해 쿠폰 수락 여부를 답한 구조입니다.

| 항목 | 값 |
|---|---|
| 행 수 | 12,684 |
| 열 수 | 26 (설명 변수 25개 + 타깃 1개) |
| 타깃 | `Y` (1 = 수락, 0 = 거절), 수락 비율 56.8% |
| 추정 응답자 수 | 약 590명 |

데이터 파일은 저장소에 포함하지 않습니다. 위 링크에서 내려받아 저장소 루트에 `in-vehicle-coupon-recommendation.csv`로 두면 노트북이 그대로 동작합니다.

### 데이터를 다룰 때 알아야 할 점

관찰 과정에서 확인한 구조적 특징입니다. 전처리와 평가 설계가 여기서 나옵니다.

- **응답자 단위 구조.** 응답자 ID는 없지만 특성 컬럼 조합으로 복원할 수 있고, 한 사람의 응답이 22행에 걸쳐 반복됩니다. 행 단위로 무작위 분할하면 같은 사람이 학습과 평가 양쪽에 들어가 성능이 과대평가됩니다. 응답자 단위 그룹 분할이 필요합니다.
- **설계된 시나리오.** 상황 조합은 201가지뿐이며, 목적지가 Work이면 항상 7AM에 혼자인 식으로 변수 간 제약이 강합니다. 상황 변수들은 서로 독립이 아닙니다.
- **설문 응답의 한계.** 실제 사용 기록이 아니라 "쓰겠다"는 답변입니다. 논리적으로 맞지 않는 응답이 소수 섞여 있습니다.
- **가장 강한 신호는 파생 변수에 있습니다.** 제안된 쿠폰 업종을 평소에 얼마나 자주 가는지가 원본의 어떤 단일 컬럼보다 수락 여부를 잘 설명합니다.
- **효과가 쿠폰마다 다릅니다.** 유효 시간, 거리, 시각의 영향이 업종에 따라 크게 달라집니다. 전체 평균으로는 보이지 않는 상호작용입니다.

자세한 관찰 결과와 각 컬럼의 의미는 [`data.md`](data.md)에 정리되어 있습니다.

## 진행 방식

데이터를 다루는 모든 단계를 노트북에 남기되, 코드보다 **왜 그렇게 했는지**를 먼저 적습니다.
각 노트북은 아래 세 요소를 반복합니다.

1. **의도.** 이 셀에서 무엇을 확인하거나 바꾸려 하는가
2. **관찰.** 실행 결과에서 무엇이 보였는가
3. **결정.** 그래서 무엇을 어떻게 처리하기로 했고, 대안은 왜 택하지 않았는가

### 단계

| 단계 | 내용 | 상태 |
|---|---|---|
| 1. 관찰 | 컬럼 의미, 분포, 결측, 중복, 변수 간 제약, 응답자 구조 파악 | 진행 중 |
| 2. 정제 | 정보 없는 컬럼 제거, 중복과 모순 응답 처리, 결측 처리 방침 결정 | 예정 |
| 3. 분할 | 응답자 단위 그룹 분할, 무작위 분할과의 비교 | 예정 |
| 4. 전처리와 피처 엔지니어링 | 순서형·명목형 인코딩, 거리 변수 통합, 업종별 방문 빈도 파생 변수 | 예정 |
| 5. 모델 비교 | 기준선 설정, 후보 모델 교차검증 비교, 선정 근거 기록 | 예정 |
| 6. 학습과 튜닝 | 선정 모델 학습, 하이퍼파라미터 탐색 | 예정 |
| 7. 평가 | 발송 대상 집단의 수락률, 발송 기준별 대상 수와 수락률 변화, 쿠폰 종류별 지표, 오분류 분석 | 예정 |
| 8. 적용 | 업종과 유효 시간을 입력하면 발송 대상과 예상 수락률을 보여주는 발송 시뮬레이션 | 예정 |
